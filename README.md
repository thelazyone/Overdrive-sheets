# Overdrive-sheets

A fast and dirty procedural builder to generate ship sheets for Full Spectrum Overdrive.

Two implementations share the same `fonts/` and `resources/` assets at the repo root:

- **`web/`** — SolidJS + Vite, client-only, live SVG preview, PNG/JSON export, slot-based ship templates.
- **`python/`** — original Pillow rasterizer, retained for reference and batch generation.

## Web Version

Requirements: Node 18+.

**GitHub Pages** (after you enable it — see repo workflow): the builder is deployed under  
`https://<user>.github.io/<repo>/overdrive/` (e.g. `/Overdrive-sheets/overdrive/` for this repository). Pushes to `main` that touch `web/`, `resources/`, or the Web workflow run CI and publish automatically.

```
cd web
npm install
npm run dev                         # http://localhost:5173/
npm run build                       # static site in web/dist/
npx tsc --noEmit                    # typecheck
npx tsx scripts/verify-ships.ts     # validate presets + legacy ships + library
```

Web-specific presets live in `web/src/presets/*.json` and are selected via the toolbar dropdown. Reusable systems live in `web/src/core/library/systems.json` and are referenced by slot allow-lists.

### Print modes

“Print fleet” offers two ways to get a sheet onto paper:

- **Custom loadout** — the original output: each ship prints as one finished A5
  console with its currently installed systems. Changing a loadout means
  reprinting the sheet.
- **Modular class** — print once, re-loadout forever. The console prints with
  every *slot* left as a uniform blank space, and each slot option prints as a
  cut-out tile sized to drop onto any of those spaces. Fixed (inline) systems
  stay printed on the console, since they can't be swapped anyway. Cut the tiles
  out once; after that you rearrange the ship by moving cardboard instead of
  reprinting.

  On A4 two A5 sheets stack per page, so a class whose tiles fit one tile page
  comes out as a single sheet of paper: console on top, modules below.

All cut-outs of a class are one fixed size — section tiles and
engine tiles each have their own standard box, and a tile always prints at
its full box size so it matches the blank space it covers.

Systems are marked by which column they belong to, so a cut-up pile stays
sortable: a **left** system has its top-left corner cut off on the diagonal, a
**right** system its top-right, and a **centre** system stays square. This
applies to every system on both print modes — swappable tiles, the blank spaces
they drop into, and fixed built-in systems alike — so a column reads the same
way everywhere. Size is `TILE_CORNER_CUT` (≈3.6 mm printed).

The `Modular` toolbar toggle previews all of this live and warns if a system
outgrows its box. Sizes are the `MODULAR_*` / `TILE_CORNER_CUT` constants in
`web/src/core/render/sheetLayout.ts`.

### Fonts

The web app uses Google Fonts (`Titillium Web` + `Orbitron` as an Eurostile Extended stand-in). The shared `fonts/` folder is only consumed by the Python tool — see `TODO.md` for why and how to swap in a real Eurostile later.

## Python Version

Requirements: Python 3.x with `pillow` and `svglib` (no venv needed).

```
python python/ship_creator.py                               # generate every ship in python/ships/
python python/ship_creator.py -s python/ships/starliner.json
```

Ship JSONs live in `python/ships/`. Output `.jpg` sheets are written next to them.

## Combinator (designer tool)

Tiny tkinter UI for visualising which ships/systems are available for every

```
python combinator/main.py
```

### Fixed-feature console layout

The web console reserves identical mask footprints for the reactor, quarters
(formerly Mess), and shields on every ship. These are required class features,
not systems: they have no loadout selector, system damage flags, or modular
cut-outs. Reactor energy-damage hit thresholds are not yet defined.

Front shields sit above the reactor and rear shields below it. Each has nine
interlocking hexagons (five left, four staggered right), including a red off
position nearest the reactor. Charge grows outward; recharge steps are yellow
and unavailable outer positions grey. Quarters and med bay sit at bottom left,
to the right of the rear track. Crew and reactor capacities are written inside
fixed footprints. All geometry lives in `FEATURE_LAYOUT` in `sheetLayout.ts`.

Legacy `mess` and wrapped feature records migrate on import. An unselected
legacy feature slot takes its first option. When a saved ship matches a preset,
that class supplies its fixed features. New exports use `quarters` and plain
feature records. The original Python generator retains its historical format.

Mask geometry is generated by `shieldGeometry.ts` and `reactorGeometry.ts`.
The revised shields union nine regular hexagons with **5.2 mm sides** and
vertical left/right edges: five centres at 9.5 mm vertical pitch, plus four
offset 4 mm right and 4.75 mm down. This explicit side length gives about
9.007 mm across flats (not 8 mm). Reactor circles are 10 mm diameter, three
left and four right, bounded by their rounded convex envelope. Quarters cells
are 8 mm squares. PDF export preserves actual scale: A4 holds two sheets with
a 1 mm gap and no scaling margins; print at 100% / actual size.

The L-shaped mask is a separate physical overlay and is not printed on the
card. Feature labels and capacities sit inside the hexagons, circles, and
square apertures. Quarters use a 3×2 grid of 8 mm squares with a 0.5 mm border,
then a 2.5 mm gap and a 1×2 med-bay grid with the same border. The combined
footprint is 36.5×17 mm; its geometry is in `quartersGeometry.ts`.
